# AGENTS.md

## What this is

**emaki.lol** is the website for [Emaki](https://github.com/alkaline-software/emaki), a Quarto site served at <https://emaki.lol>. It has a landing page with the handscroll alone at its head, small, which keeps what the app is for the shift under it, then the shift and the figures; a Docs section with a sidebar, as Kaku's docs are laid out, in five groups with a line between: Get Started (`docs/index.qmd`, the section's address); Main System, the two things always in the window, the sidebar (Projects) and the Chats; Panels, the two at the chat's sides, Files and Terminal; Margins, the two in the chat's margins, Outline and Agent CLI; then Settings and Keys, a size down; and About. The navbar is four things, as Kaku's is: the name, the app's latest version, Docs and About; the releases live on GitHub. The landing page says what the app is, an ADE, an agentic development environment, against the IDE, then how to start in three steps (the app, the two agents, GitHub if wanted), and then what is in it, in the docs' groups: Main system, its two parts, Panels, its two, and Margins, its two, a card and a figure a part, each card's name the way to its page; the docs pages say how each part works, one page a part, in the same order.

Since v0.4.0 the app has two panels, not four: the files panel at the chat's left and the terminal at its right, each with a button at an end of the strip over the chat. The outline is a drawer that slides out into the chat's left margin, and the agent CLI takes the chat's place (the CLI layout; the chat is the rendered layout), each from a seam in the chat's margin, a line down the margin with a knob halfway, shown while the pointer is near. The site's groups are the app's settings' two choices under Panels: Side panels, which the site calls Panels, and Margins. The app's code and its shortcuts still say "shell terminal"; the site says the Terminal Panel, or the terminal, as the person asked, and only the Shortcuts figure keeps the app's own label.

The app's own repo is checked out beside this one, at `/Users/pingfan/Documents/GitHub/software/emaki` (`../emaki` from here). Its `AGENTS.md` is what the app is and the rules it holds to; read it before writing about how the app behaves.

## The standard

The site is held to the level of Awwwards, the Webbys and the FWA: minimal, calm, intuitive, finished in every state. `docs/design.md` is that standard: the rules, the palette and its roles, the faces, the page, every element, the motion, and how a change is checked. Read it before changing anything a person sees, and meet it unasked. A page that reads well but breaks a rule there is not done.

## The one idea

**The site describes the app; the app is the source of truth.** Every claim on these pages, every shortcut, face and file name, comes from the app repo. Check it there before writing it here, and never describe a feature the app does not have.

## Running it

```sh
quarto preview   # http://localhost:5680
quarto render    # into _site/
```

Pushing to `main` renders the site and publishes it to the `gh-pages` branch; Netlify serves `emaki.lol` from there. A pull request renders but does not publish. So a push to `main` is a deploy: never push without the person saying so. Nothing on the site is written from the app's releases at render time: the version in the navbar is read by the browser, so a release needs no render here.

## Rules

- **The version in the navbar is the browser's to read.** `_quarto.yml` writes the word "Releases" with the id `nav-version` and the link to the releases on GitHub; `js/navbar-widgets.js` swaps the word for the latest tag, cached for a few hours: from GitHub's latest release, then, when GitHub refuses (60 requests an hour to a network not signed in), jsDelivr's latest tag of the repo, then the last one the browser kept. The word shows only when none can be had. No version is ever written into a page. Testing the site in fresh browsers spends that hour's 60 in a few dozen loads, and the person's own browser on the same network then sees the fallback; the jsDelivr step is why it still shows a version.
- **Only `*.qmd` files render** (`project.render`: the root's and `docs/`). A markdown file anywhere (`docs/design.md`, this file) is not a page, and Quarto would make one of it without that list. A new docs page goes in `docs/` and in the sidebar's `contents` in `_quarto.yml`, which is also the order the foot of each page walks (`page-navigation`); an entry whose text is `---` is the line between two groups, and a `section` with no `href` is a group's label (the sheet hides its toggle, `bread-crumbs: false` keeps it off the title). Quarto's walk at the foot stops at a line, so `js/page.js` fills the way across the groups from the menu. The page is Kaku's width (`grid`: 220 for the menu, 804 for the words, 200 for the table of contents at the right, 28 between).
- **A thing beside the chat is ⌘⇧ and its first letter**, as `shortcuts.rs` binds them: F for the Files Panel, S for the Terminal Panel (the app's shell terminal), O for the Outline's drawer, L for the layout switch (the Agent CLI in the chat's place, or the chat back), G for git's Changes sheet and V for a file's two views. The sidebar's is ⌘⇧B (and ⌘B), at the head of the Keys page's first table, named for what it shows: the projects and their sessions. There is no ⌘⇧A: the agent CLI is the layout, not a panel.
- **A docs page is one part of the app**, named as the app names it, with a title and one line under it, and `##` sections with an icon each (`{.i-<name>}`). A part that has a key carries it beside its title (`title: "Files Panel [⌘⇧F]{.kbd}"`, with `pagetitle` the name alone for the tab), and the line under it does not repeat the key. In the words the two panels are named in full, each word capitalized, the Files Panel and the Terminal Panel, never the shell terminal; the two in the margins are the Outline, a drawer, and the Agent CLI, the CLI layout, and neither is called a panel. "Seam" is the app's word for what opens each, and the site uses it. What belongs to another part is a link to that page, not a second telling. The keys are on `docs/keys.qmd` alone, in two groups as the app binds them: `⌘⇧` and a letter shows, hides or switches something beside the chat, `⌘` and a letter opens a page or does one thing; a last section says Settings, Shortcuts changes them.
- **`_hero.html`, `_download.html` and `_download-step.html` have no blank line, not even one of spaces alone, and nothing under a div indented four spaces, however deep it nests.** Pandoc reads what stands between a div's tags as Markdown: a blank line ends the block, and a line indented four spaces becomes a code block. An svg's inside is left alone.
- **A `<figure>` gets Quarto's `figure` class**, and `figure.figure { display: block }` outranks a rule with one class. A figure whose display the sheet sets is selected from its parent (`.parent > figure`), or the rule silently loses.
- **Do not hand-edit the handscroll's layer paths.** They are generated by `scripts/home-scroll.py` in the app repo; re-copy them when the figure changes there. The constants in `js/hero-scroll.js` are the app's, so the two move alike; change them only to follow the app. One is the site's own: the box is 400 wide for the app's 300, a longer sheet so the figure is wide and short at the page's head (`W`; `_hero.html`'s rest geometry, its right roll, edges, clip and the layers' offset, are drawn for it). 400 is as long as the landscape still covers the sheet at the farthest wind.
- **The keyboard is the browser's.** ⌘F on a Mac, Ctrl+F elsewhere, opens the search (`js/navbar-widgets.js`), and that is the only key the site takes: Quarto's own letters for the search (f, /, s) are turned off in `_quarto.yml` (`search.keyboard-shortcut: []`), and there is no shortcuts overlay, no button for one, and no bare letter that moves the page.
- **The navbar's GitHub link points at the app repo, not this one.** `js/navbar-widgets.js` reads the owner and repo from that link for the stars and forks, and skips the version's link, which also goes to GitHub, by its `nav-version` id.
- **Colors are tokens** (`docs/design.md`, The palette): a value in `:root` and one in `body.quarto-dark`. The light page is a warm paper, as Kaku's site has it, the dark neutrals the app's own; the accent is indigo, from the icon's navy; the frame is graphite given the accent's hue (`--frame`); the mark is its amber, the spark its violet; the handscroll's title, 絵巻, is an old seal's faded red (`--seal`) and nothing else is; terracotta is Claude's color, beside its name and in the agent's terminal, and never the page's; the shift has a set of its own (`--sk-*`), used in the shift and the figures of the app's parts, and the kinds of file on the Files Panel page, and nowhere else. Each panel has one color of its own, the same in its button, its docs page's window and its figure: the files ochre, the outline mauve, the shell sage, the agent's terminal Claude's; the sidebar and the chat keep the accent. A color that is not a token is a mistake.
- **An icon is a file in `assets/icons/`**, copied from the app under the same name, and drawn through a mask (`.i-<name>` sets `--icon`). A path in a stylesheet's `url()` is written from the project's root: Quarto resolves it when it compiles the sheet and carries the file over.
- **The appearance follows the system** (`respect-user-color-scheme`), as the app's does; the toggle pins one. `css/dark.scss` must set both `$body-bg` and `$body-color`, or Quarto does not treat the sheet as dark. Its defaults carry `!default`, and so do `theme.scss`'s: Quarto lays a later sheet's defaults under an earlier one's.
- **A button is a pill with an icon:** `[Word](page.qmd){.pill .i-download}`, with `.pill-accent` for the one thing a page is for. A key is `[⌘K]{.kbd}`, never code. A procedure is `.starts`, a card a step. The rest of the elements are in `docs/design.md`.
- **A two-column reference table sets its widths** (`: {.table-keys tbl-colwidths="[26,74]"}`), or Pandoc splits it half and half.
- **Links are relative, and the docs are one level down.** A page under `docs/` sees `js/` and `assets/` as `../js/` and `../assets/`, so the scripts are loaded from the offset Quarto writes into each page (`quarto:offset`, `_quarto.yml`), the stylesheet draws the footer's icon (Quarto resolves a sheet's `url()` for every depth), and the footer's way home is the site's root, since Quarto rewrites none of the footer's paths. A page outside the docs sets `sidebar: false`, or Quarto's one sidebar shows on it too.
- **The landing page has no `title`.** The hero sets the name; `pagetitle` names the tab and the search entry.
- **Dictation is not Emaki's.** It moved to Kotoba, the studio's menu bar app (`../kotoba`); the site names Kotoba once, in Docs, Chats, The composer, and describes none of it.
- **The handscroll is one to a page.** `_hero.html` is included on the landing page and the About page; `js/hero-scroll.js` finds it by id, so a second copy on one page would stand still.
- **A figure is drawn on Hairline.** `js/figures.js` is generated: `scripts/figures/build.sh` clones Hairline at a pinned tag, bundles the figures `scripts/figures/entry.js` names, and writes it; never edit the output, and rerun the script after changing `entry.js`, a figure in `scripts/figures/emaki/` or the tag. The app's six parts (projects, chats, files, outline, shell, agent) are Emaki's, one engine on Hairline's core (`scripts/figures/emaki/window.js`), put into Hairline's own wrapper and its intensity table by `entry.js` (`OWN`): Emaki's window seen from the front, drawn faintly at the back, with the one part a figure is about standing forward of it as a layer of its own, in full, its frame bright, dashed guides back to the empty place it left, and its control bright: a panel's button in the chrome, or the seam at the chat column's edge that opens the outline's drawer or switches the layout (`seam()`, `LAYOUTS`: `left` and `right` for the panels, `drawer` for the outline inside the chat's pane with the transcript making room, `cli` for the agent CLI in the column with the chat not drawn). ## Writing

Write as the app's own docs do: plain statements, few words, nothing the reader already knows. American spelling (color, license, center), never British (colour, licence, centre), on every page and in these files. No dashes in prose: a comma, a colon or a full stop instead.

- Name shortcuts as the Mac has them, with the signs: `⌘K`, `⌘⇧O`, `⇧Tab`. The keyboard table says once that `⌘` is `Ctrl` elsewhere.
- Say what the app does now. What was tried and dropped does not belong on the site, and neither does the current version number.
- The main panel is the chat, its page Chats, as the ADE sketch names it (Agent Chat): "the chat", or "agent chat" where the agent is the point, everywhere on the site, labels and sketches included; never "conversation".
- The app is an ADE, an agentic development environment: the chat in the middle, the files, git and the terminal at its side. Say it that way, against the IDE, once, on the landing page; the other pages take it as read.
- The Outline is a drawer in the chat's left margin and the Agent CLI takes the chat's place: neither is a panel, and each opens from a seam in the chat's margin. Say "the CLI layout" and "the rendered layout" once, on Agent CLI, as the app's own names for the two; elsewhere the Agent CLI and the chat. The terminal at the chat's right is the Terminal Panel, or the terminal, never the shell terminal, whatever the app's code calls it.
- A claim about privacy or safety (no hooks, nothing written to a transcript, nothing in a session's context) must match the app's `AGENTS.md` word for word in meaning. If the app's rules change, these pages change with them.

## Checking a change

Render it and look at every page it touches in both appearances, at 1280 and 390 wide, whole and close up, in Chromium and in WebKit (Safari's engine; the two differ on SVG text), and in every state it has (`docs/design.md`, Checking: a Playwright one-liner shoots a page). A change to `css/`, `js/`, `_hero.html` or `_download.html` is checked on the landing page, where all three meet, and a change to an element on every page that has one.
