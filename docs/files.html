Files Panel

⌘⇧F: the project’s folder as a tree, a pane for any file, and git on top of it.

The tree

The project’s folder, with git’s marks on it: a letter on a changed file, a dot on a folder with changes under it, ignored files dimmed. It works like a file manager: drag in from Finder, drag rows to move them, cut, copy, duplicate, remove (⌘⌫, to the Trash) and undo (⌘Z). New File and New Folder are at the head, and a file the agent writes appears as it lands.

Open and edit

Click a file and it opens in a pane between the tree and the chat; click it again to put it away. The enlarge button gives the pane the chat’s room. ⌘S saves, ⌘W closes, and nothing unsaved is lost without asking. Format on save covers ten languages and is off until you turn it on.

Code comes with line numbers, colors and a gutter mark per git change, with a card to see or revert it. Every kind of file is drawn for what it is:

  • Code every language, colored
  • Markdown as it reads, or as written
  • CSV and TSV a grid you can edit in place
  • Parquet a table with each column’s type
  • Word pages you can type in and format
  • Excel cells with their number formats
  • PowerPoint slides as they look
  • PDF sharp at any width, with search and page previews
  • HTML in the system’s web view
  • Pictures at their own size

Git

In a repository the branch is named at the tree’s head. Click it to switch, make a branch (⌘⇧N) or publish one; Fetch and Pull sit at the list’s foot. A switch with uncommitted changes asks whether to leave them or bring them along, and goes through only when every change lands where you asked.

The Changes pill (⌘⇧G) opens the sheet: tick the files, write the message, commit (⌘↩︎), push (⌘P). History browses the commits: Undo takes back the newest while the remote does not have it, Revert takes back any one as a new commit. Nothing is committed, pushed or pulled without a click that says so.
